# KHODIYAR INFRAPROJECT — DEVELOPMENT & SEO RULES

## 1. PURPOSE

This file contains the permanent development rules for the KHODIYAR INFRAPROJECT website.

Every future modification, feature, SEO improvement, content update, bug fix, redesign request, and optimization must follow these rules.

The website is a production website.

The primary principle is:

> BUILD ON TOP OF THE CURRENT WEBSITE — NEVER DESTROY THE CURRENT WEBSITE.

---

# 2. CORE RULE

## ONLY MAKE THE REQUESTED CHANGES. CHANGE NOTHING ELSE.

If the user requests one specific change:

- Make that change.
- Preserve everything else.
- Do not redesign unrelated sections.
- Do not rewrite unrelated content.
- Do not change working functionality.
- Do not change routing unnecessarily.
- Do not replace the existing architecture.
- Do not remove existing features unless explicitly requested.

Do not make "helpful" changes that were not requested.

---

# 3. PRESERVE THE EXISTING ARCHITECTURE

The current application architecture must be preserved.

Do not rebuild the project from scratch.

Do not migrate frameworks or technologies unless explicitly requested.

Preserve:

- React
- Vite
- TypeScript
- Existing routing architecture
- Existing component structure
- Existing data structure
- Existing styling system
- Existing assets
- Existing pages
- Existing reusable components
- Existing business logic

When adding functionality, integrate it into the existing architecture.

Prefer small, controlled modifications over large rewrites.

---

# 4. ADDITIVE DEVELOPMENT

Whenever possible:

ADD instead of REPLACE.

Examples:

- Add a new SEO configuration instead of replacing the page architecture.
- Add a new service instead of rebuilding the services system.
- Add structured data instead of replacing existing components.
- Add a new section instead of rewriting the entire page.
- Add a new utility instead of duplicating logic.

Existing functionality must remain operational after the change.

---

# 5. PROTECT SHARED COMPONENTS

Be extremely careful when modifying shared components.

Examples:

- Header
- Footer
- BrandLogo
- QuoteModal
- SearchModal
- FloatingWhatsApp
- MobileConversionBar
- ScrollToTop
- AnimatedCounter
- Shared buttons
- Shared layout components

A change to a shared component can affect the entire website.

Before modifying a shared component:

1. Understand where it is used.
2. Check its existing behavior.
3. Make the smallest necessary change.
4. Verify that all pages still work.
